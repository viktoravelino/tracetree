# tracetree — conventions for agents and humans

tracetree reads the transcripts Claude Code writes under `~/.claude` and serves
them as a live dashboard: projects, sessions, the spawn tree of subagents, and
the messages between them.

## Ground rules

- **Never push to `main` and never merge a pull request.** `main` requires a PR
  with `typecheck`, `lint`, `smoke` and `package` green. A repository admin can
  bypass that, and the admin is the maintainer, not you. Open the PR, get the
  checks green, and stop — say it is ready and leave it. The only exception is
  the maintainer explicitly saying to push directly, for that change; a previous
  yes does not carry over to the next one.
- **Never write to `~/.claude`.** It is the user's real transcript history and
  this tool only ever reads it. The index is derived data: deletable,
  rebuildable, and never a source of truth.
- **Never commit real transcript data.** `data/` and `.demo/` are gitignored and
  must stay that way. `bun run demo` writes a synthetic `~/.claude` for anything
  you need to demonstrate, screenshot, or test against.
- **Ask before starting a long-running server.** The maintainer usually has one
  on the default port already, and two writers on one SQLite file is how you get
  `SQLITE_BUSY`.

## Stack

Bun is not an implementation detail. `bun:sqlite`, `Bun.serve`'s HTML imports
and native TypeScript execution are all load-bearing, which is why the package
ships TypeScript unbuilt — there is nothing to gain from compiling to JavaScript
that Node still could not run.

- React 19, shadcn/ui in the **`base-mira`** style on **Base UI** — not Radix.
- Tailwind v4, CSS-first (`@theme inline` in `web/styles.css`), no JS config.
- `react-markdown` with `remark-gfm`, `remark-breaks` and `rehype-sanitize`.

## Layout

| path                        | what                                                                                 |
| --------------------------- | ------------------------------------------------------------------------------------ |
| `src/`                      | reader and server: `cli`, `ingest`, `db`, `server`, `watch`, `live`, `repo`, `paths` |
| `web/`                      | the dashboard; `components/ui/` is generated by the shadcn CLI                       |
| `scripts/demo.ts`           | writes a synthetic `~/.claude`, indexes it, serves it                                |
| `scripts/verify-package.sh` | packs, installs into an empty project, serves it                                     |
| `scripts/release.sh`        | one-command release                                                                  |
| `.github/workflows/`        | `ci`, `release`, `metrics`                                                           |

## Invariants

Change any of these only if the maintainer asks for that change specifically.

- **The server binds `127.0.0.1`.** There is no authentication of any kind, so
  the bind address is the entire access control: anything that reaches the port
  reads every message, tool call and pasted image in the index. `--host` exists
  to override it deliberately. Never change the default.
- **No `rehype-raw`.** Transcripts contain arbitrary model output; raw HTML is
  never parsed into the page.
- **Runtime dependency vs devDependency is decided by what the _server_ needs.**
  Anything `web/styles.css` or `bunfig.toml` pulls in when a page is built —
  `tailwindcss`, `bun-plugin-tailwind` — is a runtime dependency. A checkout
  cannot catch a mistake here, because it has every devDependency installed;
  `scripts/verify-package.sh` can, and exists because this shipped broken once.
- **Ingest is incremental.** Transcripts are append-only JSONL and
  `ingest_state` holds a byte offset per file. Do not make a change that
  requires re-reading everything.
- **When a message seems to be missing, grep the raw JSONL, not the index.** If
  it is absent from both, the ingest filter is wrong; the index agreeing with
  itself proves nothing. Mid-turn user messages, for instance, arrive as
  `type: "attachment"` with no `.message` at all.

## Working here

```bash
bun run typecheck
bun run lint                 # oxlint; format with `bun run format` (oxfmt)
bun run demo                 # synthetic ~/.claude, indexed, served on :4300
bun run demo --no-serve      # what CI runs
scripts/verify-package.sh    # the packaged install actually works
```

- **Releases are one command**: `bun run release patch` (or `minor`, `major`, or
  an explicit version). It runs the checks, commits, tags and pushes; the tag is
  what publishes. Never tag by hand. `DRY_RUN=1` rehearses it.
- Commit subjects are `type(scope): summary` in the imperative. Explain why in
  the body when it is not obvious. No AI attribution and no emoji.
